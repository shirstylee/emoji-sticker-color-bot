# Подготовка к публичному GitHub

Команды выполняются из корня репозитория. Репозиторий содержит исходный код,
а рабочие секреты, базы и пользовательские материалы остаются локальными.

## Проверки перед отправкой

```bash
git status --short
python scripts/check_publication.py --history
python -m ruff check .
python -m mypy app
python -m pytest -q
python -m app.main --check
```

Используйте Python из проектной `.venv`. Проверка истории работает только с
имеющимися локально ссылками; перед аудитом существующего GitHub-репозитория получите
нужные удалённые ветки и теги. Просмотрите также GitHub issues, PR, Actions artifacts,
releases, wiki и настройки интеграций — они не входят в локальное дерево исходников.

Коммиты содержат имя и email автора. Для новых коммитов можно включить приватный
GitHub noreply email из настроек аккаунта. Изменение email в старых коммитах меняет
их хеши и требует согласованной замены опубликованной истории. Сделайте локальную
резервную копию и не загружайте резервные refs в публичный репозиторий.

## GitHub

1. Отправьте проверенную ветку `main` и дождитесь успешного CI. Тестам не нужны
   repository secrets, токен Telegram и производственная база.
2. Включите secret scanning, push protection, Dependabot alerts и private vulnerability
   reporting, если они доступны для репозитория. См. [GitHub Docs](https://docs.github.com/en/code-security).
3. Для ветки `main` настройте ruleset с обязательным CI и проверкой pull requests.
   Workflow использует `contents: read`, стандартный `pull_request` и действия,
   закреплённые полными SHA. Он не публикует сайт и не развёртывает бота.
4. После проверки файлов, истории и материалов на GitHub смените видимость
   репозитория на Public в настройках. Включение Public — отдельное действие владельца.

## Лицензия и развёрнутые копии

Сохраняйте LICENSE и NOTICE. При публикации или работе изменённой сетевой версии
соблюдайте AGPL-3.0-only, в том числе предоставляйте соответствующий исходный код
пользователям. Укажите в `SOURCE_CODE_URL` открытый репозиторий или архив именно
запущенной версии; ссылка отображается в меню «Информация».

Ссылки на закрытый репозиторий недостаточно для пользователей, у которых нет к нему
доступа. Не добавляйте в публикуемые исходники рабочие токены или пользовательские данные.
AGPL разрешает форки и коммерческое использование при соблюдении своих условий;
она не предоставляет права на чужие стикеры и не запрещает любое копирование кода.
