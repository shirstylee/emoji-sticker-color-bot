# Сообщение об уязвимости

Если вы нашли утечку данных, обход ограничений файлов, выполнение команд, проблему
прав доступа или токен в истории, не создавайте публичный issue с подробностями.

Используйте [приватное сообщение об уязвимости на GitHub](https://github.com/shirstylee/emoji-sticker-color-bot/security/advisories/new),
если этот канал включён. Если форма недоступна, свяжитесь с сопровождающим через
[техническую поддержку](https://t.me/ragedick), сначала описав только тип проблемы.
Не отправляйте работающий токен, базу пользователей, `.env` или пользовательские файлы.

Полезны хеш коммита, версия Python и ОС, безопасный пример воспроизведения и описание
последствий. Для примеров используйте синтетические данные и собственного тестового бота.
Сопровождается текущая ветка `main`; гарантированных сроков ответа нет.

## Если секрет уже попал в Git

Сначала отзовите и замените токен через его поставщика (для Telegram — @BotFather).
Затем очистите историю и проверьте ветки, теги, копии и опубликованные артефакты.
Удаление `.env` из последнего коммита не удаляет его старые версии.
См. [инструкцию GitHub по удалению чувствительных данных](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

`scripts/check_publication.py --history` проверяет известные шаблоны ключей и
приватные пути во всех локальных Git-ссылках без вывода найденных значений.
Это дополнительная проверка; она не обнаруживает произвольный секрет любого формата
и не заменяет проверку истории, изображений, GitHub secret scanning и push protection.
