# Данные при работе бота

Этот документ описывает текущую архитектуру, а не утверждает отсутствие обработки
персональных данных. Бот получает сообщения через Telegram и использует идентификаторы
пользователя и чата для ответа, очереди, ограничений и отмены задачи.

## Обычные пользователи

Контекст задач, идентификаторы, состояние и счётчики ограничений находятся в памяти
процесса. Исходные файлы, предпросмотры и результаты временно записываются в
`TEMP_ROOT` внутри каталога со случайным идентификатором задачи.
Отдельная история обычных пользователей в SQLite не создаётся.

После полного завершения, отмены или выхода из активной задачи временный каталог
удаляется. Одиночный результат с дополнительными кнопками и частичная ошибка могут
оставаться активными до действия пользователя или таймаута неактивности
(`JOB_IDLE_TIMEOUT_SECONDS`, по умолчанию 900 секунд).
При старте приложения остатки в `TEMP_ROOT` очищаются. Каталог должен быть выделен
только этому боту и не содержать другие данные. При аварии процесса очистка может
произойти только при следующем запуске.

## Постоянные данные

SQLite хранит служебные сведения об администраторах (включая Telegram ID, роль,
язык и созданные ими наборы), настройки приложения и агрегированную статистику.
Это исключение из правила отсутствия пользовательской истории.
Логи проходят фильтрацию чувствительных полей; фильтр не является гарантией удаления
любых личных данных из произвольного текста ошибки.

## Внешние сервисы

Telegram получает исходные сообщения, результаты и данные создаваемых наборов.
Удаление локального временного каталога не удаляет сообщения и файлы на стороне
Telegram. Кнопка подбора цвета открывает внешний сайт из `COLOR_PICKER_URL`.

При самостоятельном развёртывании отдельно учитывайте настройки сервера,
системные журналы, резервные копии, внешние сервисы и доступ к SQLite и `.env`.
