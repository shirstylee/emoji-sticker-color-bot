# Участие в разработке

Для работы нужен Python 3.12+ и локальное виртуальное окружение. Команды выполняются
из корня клонированного репозитория. В Windows используйте `.venv\Scripts\python.exe`
вместо `.venv/bin/python` в примерах ниже.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m app.main --check
```

Для тестов и offline-диагностики не нужны токен бота, доступ к Telegram или настоящий
пользовательский файл. Не запускайте polling во время тестов. Для ручного запуска
настройте отдельного тестового бота в локальном `.env` по README.

Перед pull request:

```bash
.venv/bin/python -m pip check
.venv/bin/python -m ruff check .
.venv/bin/python -m mypy app
.venv/bin/python -m pytest -q
.venv/bin/python scripts/check_publication.py --history
```

Описывайте в PR проблему, итоговое поведение и выполненные проверки. Изменения
интерфейса должны учитывать русскую и английскую локализации. Для изменений обработки
файлов и задач особенно важны отмена, частичные ошибки и удаление временных данных.
Синтетические тестовые изображения предпочтительнее пользовательских материалов.

Версии прямых зависимостей должны совпадать в `pyproject.toml`, `requirements.txt`
и `requirements-dev.txt`, а разрешённое окружение — в `requirements.lock`.
После обновления зависимостей проверьте установку в чистом окружении и CI.

Не включайте в PR `.env`, токены, Telegram ID пользователей, базы, логи, приватные
переписки и локальные настройки редактора. Историю с ошибочно попавшим секретом
нельзя исправить только удалением файла: следуйте SECURITY.md.

Оригинальный код распространяется под AGPL-3.0-only. Вклад в проект должен допускать
распространение на этих условиях; сохраняйте уведомления об авторстве и лицензиях.
Не добавляйте чужие материалы без подходящего разрешения.
